# Startup & distribution (Phase 6)

## Goal

Ship Kuality as **one** `kuality.exe` that users can install (Inno Setup, per user) or unzip (portable), with an
optional start at logon, normal or elevated, an app icon and version info, and a size-optimized release build.

## Behavior (user-visible)

### One executable, several modes

| Command line | Mode |
|---|---|
| `kuality.exe` | Core (tray, widgets, Hyperkey, shortcuts). Unchanged: second instance exits 0. |
| `kuality.exe --settings [--core-pid <pid>]` | Settings window, a **separate process** of the same exe. Same rules as before: one window at a time, closes (after flushing saves) when the core exits, started alone it attaches to / starts the core. |
| `kuality.exe --startup <off\|normal\|elevated>` | Sets the start-at-logon entry and exits (used by the installer and uninstaller; the settings window calls the same code). Exit code 0 = done, 1 = failed, 2 = UAC prompt cancelled. |
| `kuality.exe --startup-task <create\|delete> --user <SID>` | Internal: the elevated helper started through UAC. Only touches the scheduled task. |

Unknown arguments are logged and ignored (the core starts). The core starts the settings window as
`kuality.exe --settings --core-pid <pid>` from `current_exe()`; the "open `config.json`" fallback stays.
Process checks that used the image names `kuality.exe` / `kuality-settings.exe` now use this exe's own file name
(a renamed exe keeps working); the settings window is still found by its title.

Release build: GUI subsystem for every mode (no console). Debug build: console subsystem, as today (a settings
window started by a debug core shares its console).

### Start at logon (General tab)

New section "Startup" with two switches:

- **Start with Windows** — on: a `Kuality` value in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` with
  `"<path of this kuality.exe>"`. No UAC.
- **Run as administrator** — only enabled while "Start with Windows" is on. On: the Run value is replaced by a
  scheduled task that starts Kuality at logon with highest privileges (so Hyperkey and shortcuts also work over
  elevated windows). Turning it on or off shows **one** UAC prompt (none when the window is already elevated).
  Turning "Start with Windows" off while elevated removes the task (one UAC prompt).
- The two entries never coexist: `normal` removes the task, `elevated` removes the Run value.
- The switches show the **real system state** (read when the window opens and after each change), not a config
  field. If the entry points to another copy of Kuality, a hint shows its path; turning the switch off and on
  points it to this copy.
- While a change runs, both switches are disabled; a cancelled UAC prompt leaves things unchanged (no error);
  a failure shows a short error under the section.
- The elevated core is a normal core: settings window opened from it is elevated too.

### Scheduled task

- Path `\Kuality\Start elevated <user SID>` (task names are machine-wide; one per user).
- Logon trigger for that user, `InteractiveToken`, `RunLevel = HighestAvailable`, action `"<exe>"` with the exe's
  folder as working dir, no time limit (`PT0S`), runs on battery, `IgnoreNew`, priority 4 (normal; the
  default 7 would make the keyboard hook process below normal).
- Security descriptor `D:(A;;FA;;;BA)(A;;FA;;;SY)(A;;GR;;;<user SID>)`: the user can read it (the unelevated
  settings window and uninstaller check whether it exists) but not change it (an unelevated program must not be
  able to point it at another exe).
- Created / deleted with the Task Scheduler COM API (`ITaskService`), XML registration (no `schtasks.exe`, no
  temp file). Deleting the last task removes the empty `\Kuality` folder.
- The unelevated side passes its own user SID to the elevated helper, so an over-the-shoulder elevation (other
  admin account) still targets the right user; HKCU is only ever written by the unelevated side.

### Icon and version info

- `assets/icon/kuality.ico` (multi-size, 16–256 px) is embedded as icon resource **1**: Explorer, the taskbar,
  the settings window (GPUI loads resource 1) and the tray icon (loaded at the small-icon size, reloaded when the
  icon is re-added) all use it. Swapping the file and rebuilding is enough to change the logo.
- Version resource: `FileVersion` / `ProductVersion` from the workspace version, `ProductName` Kuality,
  `FileDescription` Kuality, `OriginalFilename` kuality.exe, `LegalCopyright` "MIT License".
- The `.res` file is generated by `build.rs` in plain Rust (no resource compiler, no new crate) and passed to the
  linker next to the existing manifest args.
- Until the real logo exists, a placeholder (white "K" on a blue rounded square) is committed.

### Release profile

`opt-level = "s"`, `lto = "fat"`, `codegen-units = 1`, `strip = true`, `debug = false`. **`panic` stays
`unwind`**: the keyboard hook uses `catch_unwind` to release modifiers and keep running after a panic.
The GPUI-only DLLs (Direct3D, DirectComposition, UI Automation, ICU…) are delay-loaded if measuring shows they
grow the core's idle RAM.

### Portable zip

`scripts/package.ps1` → `cargo build --release`, then `dist/Kuality-<version>-portable.zip` containing
`kuality.exe`, an empty `portable` file, `LICENSE` and `README.txt` (short: what it is, portable = config next to
the exe, how to start with Windows, how to remove). With `-Installer` it also runs ISCC (if found) →
`dist/Kuality-<version>-setup.exe`.

### Installer (`installer/kuality.iss`, Inno Setup 6)

- Per user, no admin rights (`PrivilegesRequired=lowest`), to `%LOCALAPPDATA%\Programs\Kuality`; version read
  from the exe's version resource.
- Start menu entry "Kuality" → `kuality.exe --settings` (opens the window and starts the core).
- Tasks: "Start Kuality with Windows" (checked) and its child "Run as administrator at logon" (unchecked);
  after copying, `kuality.exe --startup normal|elevated` (the elevated helper shows the UAC prompt).
- Before installing/upgrading and uninstalling: a running core is closed gracefully (`WM_CLOSE` to its
  `Kuality.Core` window, wait up to 5 s), which also closes the settings window.
- Finish page: "Open Kuality" (runs `--settings`).
- Uninstall: `kuality.exe --startup off` (removes the Run value and, with one UAC prompt only if it exists, the
  task), removes the files. `%APPDATA%\Kuality` is deleted **only** if the user answers Yes to "Also delete your
  Kuality settings?" (default No; never in silent mode).

## Config

No change. The placeholder fields `general.autostart` / `general.run_elevated` are removed from the types (the
system entry is the source of truth; old files keep them as unknown fields).

## Edge cases

- Portable copy and installed copy: only one core runs (shared mutex); the startup entry points to whichever copy
  set it (shown in the hint).
- Exe moved after enabling: the entry points to a missing file; the hint shows the path.
- Per-user install + elevated task: the exe lives in a user-writable folder, so a program running as the user
  could replace it and get admin rights at the next logon. Same trade-off as other per-user tools with an
  "always run as admin" option; documented, not prevented.
- Elevated core and unelevated settings window (Start menu): the window attaches to it (waiting on the process
  needs only `SYNCHRONIZE`); the installer cannot close an elevated core (Restart Manager / file-in-use prompt).

## Out of scope

- Auto-update, code signing, all-users install, MSIX, winget manifest.
- Real logo (coordinator delivers `assets/icon/kuality.ico` + PNGs later).

## Test plan

- Unit: argument parsing; `.res` builder (icon group / version layout); task XML; Run value read/write against
  a throwaway key `HKCU\Software\Kuality-test-<pid>` (deleted afterwards); "points to another copy" logic.
- Live (portable copy, release build): tray icon shows the placeholder; left click opens settings as a second
  `kuality.exe` process; Quit closes both; `--settings` alone starts the core; RAM before/after; exe size.
- Startup switches: only with a test value name / task name, reverted; the elevated path needs a UAC click and
  is left to the user.
- Zip: unzip to a temp folder and run once. Installer: only if ISCC is installed.
